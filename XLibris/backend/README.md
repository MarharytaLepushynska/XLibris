# XLibris
## Опис бізнес-правил та матриці переходів станів
### BookRequest
* Користувач не може створити BookRequest на свою ж книгу
* Користувач не може створити BookRequest на книгу в статусі BLOCKED
* Користувач не може створити BookRequest на книгу, якщо в нього вже є існуючий Bookrequest для цієї книги
* Не можна видалити неіснуючий BookRequest
* Якщо власник переводить книгу в статус BLOCKED, всі BookRequest на неї перезодять в статус CANCELLED
* Позичальник може підтвердити/скасувати BookRequest тільки після підтвердження власника

**Матриця переходів**
- PENDING -> APPROVED
- PENDING -> REJECTED
- PENDING -> CANCELLED
- APPROVED -> FULFILLED
- APPROVED -> REJECTED
- APPROVED -> CANCELED

### User
* Не можна побачити контактну інформацію користувача, якщо у вас з ним немає спільного Loan
* Лише адміністратор може редагувати рейтинги користувача

### Book
* Користувач може створити книгу, при її створенні книги їй автоматично присвоюється новий ID та статус AVAILABLE.
* Оновлення та видалення книги можливі лише для існуючої книги.
* Якщо BookRequest переходить у статус FULFILLED, книга переходить у статус BORROWED.
* Якщо книга переводиться у статус BLOCKED, публікується подія про блокування книги.
* При зміні статусу BookRequest система оновлює статус пов'язаної книги.

**Матриця переходів**
- AVAILABLE -> BLOCKED
- BLOCKED -> AVAILABLE
- AVAILABLE -> BORROWED
- BORROWED -> AVAILABLE

### Feedback

* Користувач не може залишити відгук самому собі.
* Один користувач не може повторно залишити Feedback для одного й того самого Loan.
* При створенні Feedback йому автоматично присвоюється унікальний ID та час створення.
* Після повернення книги власник та позичальник отримують сповіщення з пропозицією залишити відгук один про одного.

### Notification

* При створенні Notification йому автоматично присвоюється унікальний ID та час створення.
* Системні сповіщення можуть створюватися асинхронно у відповідь на доменні події інших модулів.
* Після створення Loan власник книги та позичальник отримують сповіщення про створення позики та очікувану дату повернення.
* Після повернення книги власник та позичальник отримують сповіщення про завершення позики.
* Після повернення книги власник та позичальник отримують окреме сповіщення з пропозицією залишити Feedback.
* Після створення Report сповіщення отримує лише користувач, який подав скаргу.
* Після вирішення Report сповіщення про рішення модератора отримують користувач, який подав скаргу, та користувач, якого стосується скарга.
* Після відхилення Report сповіщення отримує лише користувач, який подав скаргу.
